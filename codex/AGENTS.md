# 공통 에이전트 지침 (Codex)

- 작업 시작 시, 현재 git 저장소 이름에 해당하는 `~/agent-sync/memory/<저장소명>/MEMORY.md`가
  있으면 먼저 읽고 관련 메모리 파일을 참고할 것. 전역 컨텍스트는
  `~/agent-sync/memory/_global/GLOBAL.md`에 있다.
- 메모리는 현재 git 저장소 기준으로만 로드된다. 다른 저장소의 파일을 고칠 때는 그 저장소의
  `~/agent-sync/memory/<그 저장소명>/MEMORY.md`를 직접 읽고 관련 파일을 참고할 것.
- 세션에서 오래 기억할 가치가 있는 사실(사용자 피드백, 프로젝트 제약, 반복되는 함정)을
  발견하면 같은 폴더에 `<주제>.md` 파일 하나(사실 하나)로 저장하고 `MEMORY.md`에
  `- [제목](파일명.md) — 한 줄 요약` 형식으로 인덱스를 추가할 것. `MEMORY.md`는 색인만
  담는다 — 머리말 없이 한 메모리당 한 줄, 본문 내용은 넣지 않는다.

## 메모리 파일 형식 (Claude 자동 메모리와 동일)

메모리 파일마다 아래 머리말(frontmatter)을 쓴다. Claude 쪽 회상은 `description`을 보고
관련성을 판단하므로 구체적으로 적는다.

```markdown
---
name: <kebab-case 슬러그, 파일명(확장자 제외)과 동일>
description: <한 줄 요약. 회상 시 관련성 판단에 쓰이므로 구체적으로>
metadata:
  type: user | feedback | project | reference
---

<본문: 사실 한 가지>
```

- `type`: `user` = 사용자 성향·역할·전문성, `feedback` = 작업 방식에 대한 교정·확인된 방식,
  `project` = 진행 중인 작업·목표·제약, `reference` = 외부 자료 포인터(URL, 대시보드, 티켓).
- 본문은 사실 한 가지. `feedback`·`project`는 **Why:**와 **How to apply:** 줄을 덧붙인다.
  관련 메모리는 `[[slug]]`로 링크한다(아직 없는 slug를 가리켜도 된다).
- 같은 주제의 파일이 이미 있으면 새로 만들지 말고 그 파일을 갱신한다. 틀린 것으로 밝혀진
  메모리는 지운다.
- 상대 날짜("어제", "지난주")는 절대 날짜(YYYY-MM-DD)로 적는다.
- 저장소·git 이력에서 알 수 있는 것(코드 구조, 과거 수정 내용, 커밋 기록)은 저장하지 않는다.
- 프로젝트와 무관한 기억 — 사용자 성향, 도구·작업 방식 선호, 모든 프로젝트에 적용되는
  피드백 — 은 프로젝트 폴더가 아니라 `~/agent-sync/memory/_global/GLOBAL.md`의 해당
  섹션에 간결하게 추가한다. 이미 프로젝트 메모리에 있는 항목이 전역 성격임을 발견하면
  GLOBAL.md로 옮기고 프로젝트 쪽에서 정리한다.
